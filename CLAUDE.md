# macroecohelpers

An R package of reusable helpers for macroecology / trait-evolution analysis: binding climate, spatial, temporal, and taxonomic covariates to occurrence data frames, matching data to phylogenies, and fitting and plotting the models that follow.

## Status: this package is being rewritten, not maintained

This is a copy of `colorEvoHelpers`, written while its author was learning data analysis. The existing code is a **source of ideas, not a standard to match**. The goal is a much smaller, much better package.

What that means when working here:

- **Do not imitate the existing style.** When touching a function, bring it fully up to the standards below rather than making a minimal edit that preserves its current shape.
- **Do not preserve backwards compatibility.** Renaming functions, changing arguments, and changing return values are all expected. No deprecation shims.
- **Deleting is progress.** A function that fails the "does this belong here" test below should be removed, not polished. Git history is the archive: no `_old` files, no commented-out code.
- **Existing behavior is not a spec.** Many functions have bugs (see "Known problems"). Work out what the function was meant to do, and do that. If the intent is genuinely unclear, ask.

## Does this belong in the package?

Keep a function only if all of these hold:

1. **It is general.** It would be useful in a second, unrelated macroecology project without editing. Anything tied to one dataset, one study's column layout, one directory structure, or one machine's paths belongs in that project's repo.
2. **It does one thing.** Functions named `getPlotX`, `plotSaveX`, or `vifsAndStep` fit, plot, print, and save in one call. Split them into composable pieces, or drop them if each piece is a one-liner over an existing package.
3. **It earns its keep.** A thin wrapper around a single call to dplyr, ggplot2, or a modelling package adds a dependency and a name to learn, and nothing else. Delete it.
4. **It fits the package's scope.** The image and colour-pattern code (`extractSimpleColorStats`, `makePatternPCA`, `recolorizeSegmentDir`, `dfFromBCCPatternFolder`, `vizID`, `get_color_threshold_metrics`, and similar) comes from specific wing-colour projects and is the first candidate for removal or for moving out.

When triaging, state the verdict for each function (keep and rewrite / merge into another / move to a project / delete) and the reason, and confirm with the user before deleting in bulk.

Non-package files in the repo root (`test.R`, the `*.csv` outputs, `plots/`, `saved/`, `.RData`, `.Rhistory`, the scripts in `inst/`) are leftovers from specific analyses. They are not part of the package. Do not build on them, and do not delete untracked ones without asking.

## Standards for code that stays

### Package hygiene

- **Never call `library()` or `require()` inside a function.** Call other packages as `pkg::fun()`, or import with roxygen `@importFrom`. Declare every package in `DESCRIPTION`.
- **Keep `Imports` small.** The current code loads about 65 packages. Core tidyverse packages go in `Imports`; heavy or niche ones (brms, phyr, terra, sf, taxize, prism, and so on) go in `Suggests` and are guarded with `rlang::check_installed()`.
- **Do not use retired packages:** `sp`, `raster`, `rgdal`, `plyr`. Use `sf` and `terra`.
- **`NAMESPACE` is generated by roxygen2.** The current hand-written one (`exportPattern("^[[:alpha:]]+")` plus whole-package `import()`s) must be replaced. Export deliberately with `@export`; leave internal helpers unexported.
- **Every exported function has complete roxygen docs:** title, every `@param`, `@returns`, and a runnable `@examples` (wrapped in `\dontrun{}` only when it needs the network or large data).
- **Every kept function has testthat (3rd edition) tests.** Functions that hit the network need the fetch separated from the logic so the logic can be tested offline.

### Function design

- **Names are `snake_case`, verb first** (`bind_elevation()`, not `bindElevation()`), with a consistent prefix per family (`bind_*` adds columns, `filter_*` drops rows, `plot_*` returns a plot). One function per file, file named after the function.
- **Data frame in, data frame out.** The data argument comes first and is named `data`. Return a tibble with the same rows in the same order unless the function's job is to filter or summarise. `bind_*` functions must never silently drop rows; rows that cannot be matched get `NA`.
- **No hardcoded column names.** Take columns as arguments using tidy evaluation (`{{ }}`, `.data[[ ]]`, `all_of()`), with sensible defaults such as `lat = latitude`. Never assume `species`, `genus`, `latitude`, `longitude`, or `season` exist without the caller being able to override them.
- **No hardcoded paths.** No `D:/...` defaults, no writing to `data/` or `saved/` relative to the working directory. Cache and download directories are explicit arguments.
- **No hidden side effects.** A function does not print, plot, and save as a by-product of computing something. Plot functions return the ggplot object and leave printing and `ggsave()` to the caller. Model functions return the model.
- **No `eval(parse(text = ...))`.** Take a formula object, or build one with `stats::reformulate()`. Formulas are not passed around as strings.
- **No references to global variables** or objects from a caller's session.
- **Validate inputs at the top** and fail with `cli::cli_abort()` messages that name the offending argument. Use `cli::cli_warn()` / `cli_inform()` for messages, never `print()`.
- **Type-stable and vectorised.** Use `TRUE`/`FALSE` (never `T`/`F`), `seq_along()` (never `1:length(x)`), `purrr::map_*()` or `vapply()` (never `sapply()`), and joins from dplyr (never `merge()` or `cbind()` to attach columns). Prefer vectorised code over row loops.
- **Use the base pipe `|>`** and current dplyr idioms (`across()`, `.by`, `join_by()`). No superseded verbs (`mutate_at`, `group_by_at`, `aes_string`).
- **Be explicit about CRS and units** in spatial code. Do not approximate kilometres as degrees; project to an appropriate CRS.

### Style

Follow the tidyverse style guide, with 4-space indentation as set in `macroecohelpers.Rproj`. Comments explain why, not what. No commented-out code and no example calls left as comments at the bottom of files; those belong in `@examples` or tests.

## Known problems in the current code

These illustrate what to look for; the list is not exhaustive.

- `DESCRIPTION` still has the `colorEvoHelpers` name and the RStudio template placeholders for title, author, description, and licence. `man/` holds three stale `.Rd` files, including the template `hello.Rd`.
- `library()` calls inside nearly every function.
- Machine-specific default paths (`bindWorldClimData`, `bindBioclimData`, `makePatternPCA`, `vizID`).
- Functions that ignore their own arguments: `filterWellSampledSpecies()` takes `n` but filters on a hardcoded 5, and builds a plot it never prints.
- References to objects that do not exist in the package: `describeCols()` uses `wings$Family` and `getPalette()`.
- Broken tidy evaluation: `plotScatter()` passes column-name strings straight to `aes()`.
- Model formulas assembled by string pasting and `eval(parse())` (`getPlotLM`, `vifsAndStep`).
- Duplicates and dead versions kept side by side (`downloadDaymet.R` and `downloadDaymet_old.R`, `bindBioclimData` and `bindWorldClimData`).
- Filename and function name disagree (`bindWorldclimData.R` defines `bindWorldClimData`).
- No tests, no README, and docs on only a minority of functions.

## Workflow

R 4.2 is installed, with devtools, roxygen2, testthat, and usethis. `lintr` and `styler` are not installed. Run from the package root:

```r
devtools::load_all()                              # load the package for interactive use
devtools::document()                              # regenerate NAMESPACE and man/ from roxygen
devtools::test()                                  # run all tests
devtools::test(filter = "bind_elevation")         # run one test file
devtools::check()                                 # full R CMD check; the target is 0 errors, 0 warnings
```

From a shell: `Rscript -e "devtools::test()"`.

There is no `tests/` directory yet; set it up with `usethis::use_testthat(3)`. Until the package infrastructure (DESCRIPTION, roxygen-managed NAMESPACE, testthat) is in place, `devtools::check()` will fail for reasons unrelated to any one function, so fix that infrastructure first.

Work in small, reviewable steps: one function or one family of functions per commit, with its docs and tests in the same commit.
